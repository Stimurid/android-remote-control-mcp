# Exact-source Android TTS MCP extension

Status: **implementation candidate** (not yet device-tested). Updated 2026-11-02.

## Origin and ownership

This is a modification of Daniele Salvatore Albano's [Android Remote Control MCP](https://github.com/danielealbano/android-remote-control-mcp), distributed under GPL-3.0-or-later with its original license and copyright notices intact. Our fork: https://github.com/Stimurid/android-remote-control-mcp.

Branch: `feature/android-exact-tts`. Keep feature work isolated until CI and Android device acceptance.

## Purpose

Permit an MCP client to submit the **actual source text** for playback on the *same Android device* where the ChatGPT voice session may be running. Do not ask the conversational model to recite or paraphrase source text. Source string is split *without changing a character* and sent directly to Android's installed TextToSpeech engine. The response contains the SHA-256 of the source payload.

## MCP interface

- `android_tts_speak(text, language="ru-RU", rate=1.0)`: replace previous playback and begin asynchronously; max 160,000 UTF-16 code units. Returns state, SHA-256, total input characters, and chunk position.
- `android_tts_control(action="status"|"pause"|"resume"|"stop")`: inspection and control.

The usual device slug prefix applies. Both tools can be disabled through the existing MCP tool permissions. The MCP server's normal Bearer/OAuth authorization applies. No source text is logged by the tool wrapper (tool name, status, duration only).

## Fidelity and interruptions

* `ExactTextChunker.split` preserves exact input string, including punctuation, whitespace and Unicode; the test checks `chunks.joinToString("") == text`.
* Text is fed to the system Android TTS engine, not regenerated by a conversational LLM. **This is not a guarantee of literal audible pronunciation**: the selected TTS engine may pronounce abbreviations, numbers, punctuation and markup differently, and may have its own synthesis errors.
* During `pause`, TTS stops the current chunk. `resume` **replays the interrupted chunk from its beginning**, so a brief repetition may occur; it never silently advances past the interrupted portion. Chunks are at most 220 UTF-16 code units.
* During a real Android playback interruption, an engine error is surfaced through `status`; no automatic skipping.
* Stopping the MCP foreground server shuts down its TTS engine and stops audio. The Android audio mixer may stop or duck ChatGPT Voice or deny audio focus. **Simultaneous duplex playback is untested**.
* This project does not provide a root shell or arbitrary Android terminal. Existing Android APIs remain restricted by Android permissions and the MCP app's settings.

## Device acceptance (pending)

1. Install a fork-built debug APK on an Android 13+ test device with a Russian TTS voice installed.
2. Enable the MCP server and authorize one client. Confirm all old tools remain available.
3. Speak a 3-paragraph Russian source with punctuation and Unicode; verify the returned SHA-256 matches independently computed UTF-8 source.
4. Pause halfway through a chunk, resume, stop, and check no missing source chunks and correct state.
5. Test without a Russian voice; verify an explicit error and no false "finished".
6. Test ChatGPT Voice concurrently and document Android audio focus / microphone behavior.
7. Confirm access token gating and disabling individual TTS tools.

## Backlog (not implemented)

- Select explicit installed voice/engine (e.g. a separately installed local neural TTS).
- Android MediaSession audio controls and headset transport buttons.
- Finer-grained pause/resume with synthesis range callbacks and no repeated syllables.
- Obtain actual voice-output recording and align it with source (would require additional privacy and permissions).
